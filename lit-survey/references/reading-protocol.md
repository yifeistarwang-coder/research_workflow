# 阅读协议

## 主干：researcher 认真读，agent 准备导读

主干阅读的目的是理解问题为什么这样定义、方法为什么这样设计、结论在什么条件下成立。agent 可以定位章节、解释难点、比较前作，并整理 researcher 的反馈。

导读记录两种状态：agent 实际查看了哪些材料；researcher 是否反馈已读及其问题。没有反馈时写“未反馈”，不推测阅读进度。

建议按问题阅读：

1. 从摘要和引言确认问题、贡献与使用场景。
2. 对照前作读方法，找出继承的假设和改变的部分。
3. 读支持主要结论的实验或证明，检查比较对象、条件与适用范围。
4. 回看局限、讨论、related work 及相关附录，核对作者怎样描述与前作的关系。

阅读深度由理解需要决定。涉及关键公式、表格、图像或证明时，查看原文；分页文本可用于定位和检索，但抽取顺序和符号可能有误。较长论文按章节处理，并记录已读范围，避免遗漏支撑结论的材料。

## 导读内容

使用 [主干导读模板](../assets/backbone-note-template.md)。未读到的部分应说明缺少什么，已经读到的部分回答：

| 内容 | 需要说明什么 |
| --- | --- |
| 解决什么问题 | 前作或当时的做法卡在哪里，这篇采用什么设定 |
| 核心机制 | 方法如何工作，哪些步骤沿用前作，哪些发生了变化 |
| 关键证据 | 哪个实验、推导或观察支持结论，在什么条件下成立 |
| 与前作的关系 | 相对哪篇改了什么，依据是作者说明还是 agent 的比较 |
| 遗留问题 | 作者承认的限制，以及当前材料尚不能回答的问题 |

每篇再给出具体阅读建议，例如“对照 A 的损失函数读第 3 节，再检查表 2 是否控制了训练预算”。

关键论断标注实际读过的页码、章节或表号，例如 `[p.3, §2.1]`。页码说明采用 PDF 页序还是印刷页码，并记录论文版本。网页原文没有页码时用章节名或锚点，不补造页码。

区分作者主张、论文报告的证据与 agent 的判断。例如：

> 作者将收益归因于更好的负样本。表 2 在相同训练步数下支持这一解释，但没有控制总计算量；现有材料不足以比较计算效率。

## Follow-up：agent 比较并总结

先看摘要和贡献说明，重点找它相对哪篇主干改变了什么。摘要不能说明的部分再读相关原文，尤其是基线设置、预算和方法差异。

每个条目通常用几句话说明：论文身份、相对某篇主干的修改、结论的适用条件，以及何时值得 researcher 补读。标明依据来自摘要还是具体章节，不把作者在摘要中的声称写成已经核验的结果。

将相近的条目合成 related work 段落。例如，一组工作都在替换检索器时，先解释它们共享的框架，再比较替换的目的和代价。保留条目索引，方便 researcher 查原文。

如果论文改变了设定、提出关键反例，或成为后续常用参照，应重新评估其阅读优先级。说明调整理由，再补主干导读。

## 处理不确定性

未取得原文时，可以交付摘要级说明和原文入口。具体记录“还需检查相同预算下的比较”，比笼统写“有待进一步研究”更有用。

新遇到的论文先核对身份并登记出处。实验数字只取自实际查看的材料；引用数记数据库与查询日期。不要为了填满模板或通过脚本检查推断数值、页码或阅读状态。
