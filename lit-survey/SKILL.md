# 文献调研

帮助 researcher 建立一个研究方向的理解，并把阅读时间放在关键论文上。

1. 先找奠基性的文章。数千引用是典型的初筛信号，再看它是否提出了领域持续沿用的问题或方法。
2. 从这些文章往后梳理：谁延续了原来的做法，谁换了视角，问题如何一步步变化。将关键转折连成主线。
3. 主干论文由 researcher 自己认真读。agent 准备导读、定位证据、协助比较；中间的 follow-up 由 agent 总结成 related work，让 researcher 大致了解它改了什么。

## 适用范围与按需执行

用户明确调用本 Skill，或任务确实需要跨论文的奠基工作筛选、研究脉络、阅读路线或 related work 时使用。单篇论文解读、教材章节讲解、概念问答、代码调试、下载 PDF、格式转换以及编辑本 Skill 本身，不自动启动文献调研。

按用户所需产物执行相关步骤：只找奠基论文时交付候选与理由；只安排阅读顺序时整理所需主线；更新已有综述时只补充受影响部分。只有完整调研才执行完整流程，不为局部任务建立整套目录或生成完整报告。

首次读取本文件后，其他材料按步骤需要加载，同一材料未变化时复用已读内容：

| 当前需要 | 参考材料 |
| --- | --- |
| 判断候选、版本或主线关系遇到具体疑点 | [领域梳理](references/field-mapping.md) |
| 准备主干导读，需要阅读方法或记录格式 | [阅读协议](references/reading-protocol.md)、[主干导读模板](assets/backbone-note-template.md) |
| 撰写 follow-up 对比，需要条目格式 | [related work 模板](assets/related-work-template.md) |

| 确定要运行某个辅助脚本 | [脚本用法](references/script-usage.md) 中对应章节 |

示例只用于解决写法疑问，不默认读取；已确定输出格式时不再加载同类模板。参考文档中的链接也按当前需要选择。

## 分工

agent 负责检索、核对论文身份、提出主干候选、整理阅读材料和撰写综述。researcher 决定哪些判断值得继续追究，并通过阅读原文形成自己的理解。agent 的导读应标明实际读过的材料；只有 researcher 明确反馈后，才能记录其已读。

这套流程适用于能检索和阅读文献的 agent。使用当前环境已有的搜索、文件和论文工具即可；附带的 Python 脚本是可选辅助。

## 1. 确定范围

从请求和已有对话中提取方向、用途、时间范围、已知论文与阅读预算。仅当缺失信息会实质改变调研目标或结论时询问；其他信息采用明确的暂定假设继续。用户给过的 anchor、预算、输出偏好和授权直接沿用。候选筛选、公开文献检索及任务内的本地笔记编辑无需逐阶段确认；对外发送、私有材料上传、付费访问或不可恢复覆盖仍须有明确且范围匹配的授权。

需要持续调研时，把范围简记在 `scope.md`。寻找奠基工作时保留追溯早期文献的余地，即使应用关注近几年的进展。

## 2. 找奠基工作

从 researcher 提供的 anchor、领域高引论文和近年综述的参考文献入手。对候选记录标题、年份、稳定标识符、引用数及其来源，并用一句话说明为何值得作为起点。

引用数先看数量级。成熟领域的数千引用通常值得优先检查；新领域、小领域需要结合发表年限和领域规模判断。核对预印本与发表版本，避免把记录拆分造成的低引用当成影响力低。

给出少量候选和选择理由。用户已指定起点时沿用；否则按调研目标选择暂定候选并继续，列明影响主线的分歧供 researcher 判断，不把候选选择设为等待批准的关卡。脚本排名不代表用户确认。

## 3. 串起主线

同时查前作和后续：参考文献帮助追溯来源，引用它的论文、近期综述和针对具体问题的检索帮助发现发展。每个主干候选回答：

- 前一篇解决了什么，留下了什么问题？
- 这一篇沿用了什么，具体改变了什么？
- 这个变化为何值得 researcher 认真读？后续哪些工作继续讨论它？

主干通常包括奠基工作，以及改变问题设定、方法思路或关键假设的文章。主干数量随方向和阅读预算确定。多个方法并行时保留分叉；若两篇之间的继承关系尚不清楚，就写清已知联系与疑点。

引用关系只能说明一篇论文引用了另一篇。把它写成方法继承或视角转变，需要原文、作者对前作的讨论或可核对的比较作为依据。主线可以用简表、文字或带关系标签的图表达。

## 4. 准备主干阅读材料

为每篇主干取得原文，整理一份导读：解决什么问题、核心机制、关键证据、与前作的关系、遗留问题。重点告诉 researcher 应该读哪些章节、比较哪些实验、带着什么问题读。

agent 写入的机制、实验数字和比较结论，应能定位到实际读过的页码、章节或表格。公式、图表和证明在文本抽取不清楚时回到原文查看。阅读范围由问题决定，不限定页数。

原文暂时拿不到时，保留条目，说明现有材料和缺失部分。researcher 尚未读过不妨碍交付导读，但不能标成已完成阅读。

导读格式可按任务裁剪，不为填满模板补造材料。

## 5. 总结中间的 follow-up

先读摘要和作者对贡献的说明；不足以判断差异时，再读相关方法、实验或 related work。每条说明它相对哪篇主干改了什么，以及 researcher 是否有必要补读。

例如：

> B 沿用 A 的问题设定，将固定的检索次数改为按置信度触发。摘要报告检索开销下降；是否使用相同计算预算还需看实验设置。若关注检索时机，建议补读方法部分。

将有关联的条目合成简短的 related work，按共同问题或修改方式组织。小修小改是比较后的判断；若发现新的问题设定、关键反例或被后续反复采用的方法，重新考虑它是否应进入主干。

只需比较少数条目时，直接交付比较结果，不要求另建完整 related work 文件。

## 6. 交付与核对

交付内容应让 researcher 看清：从哪篇开始读，主线如何发展，中间工作改了什么，还有哪些关系需要核对。篇幅按用途调整；研究机会只在有文献依据时讨论，并区分“已读论文没有回答”与“领域尚无人研究”。

完整调研先以 Markdown 保存；简短候选表、阅读建议或局部更新按请求直接交付，只创建需要的文件：

- `survey.md`：主线、关键转折、阅读顺序和仍需核对的问题。
- `backbone/`：需要的主干导读与 researcher 的阅读反馈。
- `digests/related_work.md`：需要的 follow-up 比较与简短综述。

保留完整报告在现有 LaTeX 环境可用时优先交付 PDF 的偏好；用户明确要求其他格式时遵循该要求。简短答复、中间结果和局部修改不自动探测或编译 LaTeX。完整报告的编译、检查与回退规则统一见 [报告规范](references/writing-survey.md#条件性-pdf-交付)。

### 一次交付核对

整理材料时记录证据，交付前集中核对本次新增或修改内容：论文身份与版本、关键关系的原文依据、数字及比较条件的出处、agent 与 researcher 的阅读状态。已核对且依据未变的内容复用记录；若新增材料影响旧结论，一并复核。信息不足时写清缺口和补查入口，不为填满模板补造引用数、页码或研究空白。

结构检查器仅在采用脚本生成的 `lineage.json` 与目录结构、且需要结构校验时运行一次；输入变化或检查失败时再重跑。它不适用于普通问答或简版报告。`OVERALL PASS` 只表示程序检查项通过，不能替代上述内容核对；固定格式误报按 [脚本用法](references/script-usage.md#检查文件) 处理，不将误报转成额外的用户批准步骤。

## 可选脚本

脚本支持找候选、采集参考文献、下载 PDF、抽取分页文本和检查文件结构。路径、依赖、命令及限制集中在 [脚本用法](references/script-usage.md)，需要运行时再读。

脚本当前主要向后采集参考文献，需要另行检索后续工作。也可以使用其他学术搜索、引文数据库或论文原文完成相同步骤，记录实际使用的来源即可。
